# 「新しい発見」の扱い
あなたやサブエージェントが「新しい発見」をしたとき、その多くは次のいずれかであることを肝に銘じてください。

- 意図された実装（設計意図がコメントや別レイヤーに書かれている）
- 計測・計算ミス（標本が小さい、単位や順序が違う）
- 錯覚（ノイズを傾向として読む、相関を因果と読む）
- 局所のみで判断（関数単体で正しさを論じ、呼び出し側を見ていない）
- 計器の側の誤り（測っている量が、その名前が指す量と違う）

上記をクリアした場合のみ、有用な可能性があると扱われます。

# 選択肢の提示
- ユーザーに確認が必要な場合や、複数のアプローチが考えられる場合は、選択肢を番号付きリストで提示する
- ユーザーは数字（1, 2, 3など）で回答することで、齟齬なく意思決定できる
- 各選択肢には簡潔な説明と推奨度（⭐マーク等）を付ける

**例**:
```
まとめる場所として、以下の選択肢が考えられます：

1. README.md
   - すべてのプロジェクトで有効
   - 推奨度: ⭐⭐⭐

2. このプロジェクトの skill.md
   - このプロジェクト内でのみ参照される
   - 推奨度: ⭐

3. 新しいファイル interaction_guidelines.md
   - コミュニケーションパターン専用
   - 推奨度: ⭐⭐

どれがいいですか？（数字でお答えください）
```
